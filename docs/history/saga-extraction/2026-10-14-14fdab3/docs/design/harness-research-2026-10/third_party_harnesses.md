# Third-party and open-source coding-agent harness landscape (as of 2026-10-13) versus Saga

Research scope: architecture, extension points, autonomy/loop support, unattended container operation, and auth/billing posture of the major non-Claude-Code harnesses, assessed against Saga's needs (a planner agent that decomposes specs, plus Docker-contained workers that run iterative loops, publish per-iteration status to MQTT via hooks, and read guidance files). Star counts and release dates below were pulled from the GitHub REST API on 2026-10-14 unless otherwise noted; all other claims are cited inline. Dated claims are explicit. Where I could not confirm something, it is listed under Gaps.

## KQ1. Per-harness fact sheet: architecture, extension model, autonomy, unattended container operation, auth/billing, sandboxing, popularity, 2026 events

### Takeaway
By October 2026 every major harness has converged on the same shape (headless `-p`/`exec` mode emitting JSONL, Claude-Code-style lifecycle shell hooks with JSON on stdin/stdout and exit code 2 = block, AGENTS.md, Agent Skills, MCP, subagents, session resume, ACP server mode), so the differentiators are now (a) whose subscription the harness can legally bill against inside a container and (b) a handful of distinctive mechanisms (OpenCode's server/SSE event bus, Pi's TypeScript extension events, Hermes's judge-driven `/goal` and outbound webhooks, Codex's reviewer-agent approvals and AGENTS.md layering, Gemini CLI's policy engine, Droid's autonomy tiers). Several landscape-shifting events happened in 2026: Anthropic walled subscriptions off from third-party harnesses (Jan 9 OAuth block, Apr 4 harness policy, Mar 19 OpenCode legal removal), Google replaced the open-source Gemini CLI with the closed Antigravity CLI for consumers on June 18, Roo Code was archived (May 15), Aider went dormant, Pi moved to Earendil, Goose moved to the Linux Foundation's AAIF, and OpenCode's org became `anomalyco`.

### Cited Findings

#### OpenAI Codex CLI
- Rust implementation (release tags are `rust-v0.16x`); 129,090 stars; pushed 2026-10-14; stable releases roughly weekly (`rust-v0.160.1` 2026-10-05, `0.161.0` 10-07, `0.162.0` 10-08, `0.162.1` 10-09) with alpha builds daily — [GitHub API: openai/codex](https://api.github.com/repos/openai/codex)
- Docs moved: `developers.openai.com/codex/*` now 308-redirects to `learn.chatgpt.com/docs/*` (observed 2026-10-14) — [learn.chatgpt.com/docs/non-interactive-mode.md](https://learn.chatgpt.com/docs/non-interactive-mode.md)
- Non-interactive mode: `codex exec "<prompt>"`; progress to stderr, only the final message to stdout; `--json` switches stdout to JSONL with events `thread.started`, `turn.started`, `turn.completed` (includes token usage), `turn.failed`, `item.*` (agent messages, reasoning, command executions, file changes, MCP tool calls, web searches, plan updates), `error`; `-o/--output-last-message <path>`; `--output-schema <file>` (JSON Schema-constrained final answer); `--ephemeral` (no session rollout persisted); `--sandbox workspace-write|danger-full-access` (default read-only); **`--full-auto` is no longer supported** (use `--sandbox workspace-write` or `--approve-for-me`); `--ignore-user-config`; `--ignore-rules`; `--skip-git-repo-check` (Codex requires a git repo by default); `codex exec resume --last "<prompt>"` / `codex exec resume <SESSION_ID>`; `codex exec -` reads prompt from stdin; MCP servers with `required = true` that fail to init make `codex exec` exit with an error — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode.md)
- Hooks: 12 events — `SessionStart`, `SessionEnd`, `SubagentStart`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `SubagentStop`, `Stop`, `Interrupt`. Configured in `~/.codex/hooks.json`, `~/.codex/config.toml` (`[hooks]` tables), `<repo>/.codex/hooks.json`, `<repo>/.codex/config.toml`; plugins may bundle `hooks/hooks.json`; managed hooks via `requirements.toml`. Every hook gets JSON on stdin with `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`; `Stop` adds `stop_hook_active` and `last_assistant_message`; `SessionEnd` adds `reason`. Output JSON supports `continue`, `stopReason`, `systemMessage`, `suppressOutput`, `hookSpecificOutput` (`additionalContext`, `permissionDecision` allow/deny, `updatedInput`, `decision`). Exit 2 blocks (stderr = reason). Non-managed hooks must be trusted via `/hooks` in the CLI and trust is tied to the hook's hash (changed hooks are skipped until re-trusted); `--dangerously-bypass-hook-trust` exists for one-off automation. Hooks are enabled by default (`[features] hooks = false` disables); `codex_hooks` is a deprecated alias. The page does not state whether hooks fire under `codex exec` — [Codex hooks reference](https://learn.chatgpt.com/docs/hooks.md)
- Third-party reports (unofficial): a `/hooks` TUI command has existed since v0.129.0 and headless `codex exec --full-auto` runs operate under the most restrictive example policies — [danielvaughan, 2026-05-17](https://codex.danielvaughan.com/2026/05/17/codex-cli-hooks-lifecycle-pretooluse-posttooluse-governance-enforcement/); a separate "notify" external hook that receives a JSON payload with a last-assistant-message field and can forward to Slack/OSC 9 — [danielvaughan, 2026-04-13](https://codex.danielvaughan.com/2026/04/13/codex-cli-notification-pipeline-osc9-hooks-alerts/); Stop-hook examples with `notify-send` — [danielvaughan, 2026-03-26](https://codex.danielvaughan.com/2026/03/26/codex-cli-hooks-deep-dive)
- AGENTS.md layering: global `~/.codex/AGENTS.override.md` else `~/.codex/AGENTS.md` (one file); then walk from project (git) root down to cwd, at most one file per directory (`AGENTS.override.md`, then `AGENTS.md`, then `project_doc_fallback_filenames`), concatenated root-first so files nearer cwd override; combined size capped by `project_doc_max_bytes` (default 32 KiB, later files cut off); chain built once per run (restart to pick up changes); `CODEX_HOME` can point at a project-specific profile — [AGENTS.md docs](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)
- Subagents: parallel agent threads merged into one response; built-ins `default`, `worker`, `explorer`; custom agents are standalone TOML files in `~/.codex/agents/` or `.codex/agents/` with required `name`, `description`, `developer_instructions` and optional `model`, `model_reasoning_effort`, `features.*=false` etc.; subagents inherit and **cannot override** `sandbox_mode`, `approval_policy`, `model_provider`, `mcp_servers`; global `[agents]` keys `enabled`, `max_concurrent_threads_per_session` (`max_threads` legacy alias), `default_subagent_model`, `default_subagent_reasoning_effort`, `interrupt_message`; "Current Codex releases enable subagent workflows by default" — [Subagents docs](https://learn.chatgpt.com/docs/agent-configuration/subagents.md)
- Sandboxing: macOS Seatbelt; Windows native sandbox (WSL2 uses the Linux path); Linux/WSL2 requires `bubblewrap` (`bwrap`) on PATH or a bundled helper that needs unprivileged user namespaces (Ubuntu 24.04 may need an AppArmor profile). Modes `read-only`, `workspace-write` (default for local work), `danger-full-access`. Approval policies `on-request`, `never`; `untrusted` is retired. `approvals_reviewer = user | auto_review` routes eligible approval prompts to a reviewer agent ("Approve for me") without changing the sandbox boundary — [Sandboxing docs](https://learn.chatgpt.com/docs/sandboxing.md)
- Auth: ChatGPT sign-in = subscription access; API key = usage-based billing at API rates. Device-code login (beta): enable in ChatGPT security settings (personal) or workspace permissions, then `codex login --device-auth`. Headless fallbacks: run `codex login` elsewhere and copy `~/.codex/auth.json` (examples with `scp`, `ssh`+`cat`, `docker cp`; "treat like a password"), or SSH-tunnel port 1455. Enterprise workspaces can mint Codex access tokens for trusted non-interactive workflows: `printenv CODEX_ACCESS_TOKEN | codex login --with-access-token`. Codex cloud requires ChatGPT sign-in — [Codex auth docs](https://learn.chatgpt.com/docs/auth)
- CI/CD with ChatGPT-managed auth is documented as an "advanced" path: seed `auth.json` from secure storage, let Codex refresh it in place, persist the updated file between runs; don't use for public repos; API keys "remain the simpler default"; `CODEX_API_KEY` is honored only by `codex exec` (and `codex review`, the TypeScript SDK, `codex exec-server --remote`) — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode.md)
- Plans: Free ($0, GPT-6 Luna in desktop app, rollout-gated), Go ($8), Plus ($20: web, CLI, IDE, iOS, cloud review/Slack), Pro ($100/$200/$500), Business ($20–25/user), Enterprise/Edu, or API key. Plus/Standard Business: roughly 350–3,000 GPT-6 Luna messages or 15–160 GPT-6.1 Sol messages per 5-hour window (estimates), weekly limits may apply; Pro "currently has no five-hour limit"; Plus/Pro can buy extra credits. GPT-5.5 retires from Codex 2026-10-14 — [Codex pricing](https://learn.chatgpt.com/docs/pricing.md)
- Other extension surfaces: plugins (`plugins.md`, `build-plugins.md`), skills (`build-skills.md`, `skills-and-plugins.md`), an "app-server" protocol for embedding Codex (`app-server.md`), and a migration page "from the removed Codex MCP server to the app server" (`mcp-server.md`); no dedicated compaction or exec-server page exists in the doc index — [learn.chatgpt.com/llms.txt](https://learn.chatgpt.com/llms.txt)
- Third-party: skills are lazily loaded (metadata first, full `SKILL.md` on selection); a "five-layer" customisation stack (AGENTS.md → skills → MCP → subagents → plugins), current as of v0.135.0 (May 2026) — [danielvaughan, 2026-04-12](https://codex.danielvaughan.com/2026/04/12/codex-cli-customisation-stack-unified-system/)
- ACP: available only through the `codex-acp` adapter (marked adapter-based on the ACP agents list) — [ACP agents list](https://agentclientprotocol.com/overview/agents)

#### Google Gemini CLI (and its consumer successor, Antigravity CLI)
- TypeScript/Node; Apache-2.0; 107,333 stars; pushed 2026-10-14; weekly stable (`v0.64.0` 2026-10-13, `v0.63.0` 10-06, `v0.62.0` 09-29) plus preview and nightly channels — [GitHub API](https://api.github.com/repos/google-gemini/gemini-cli); release cadence (preview Tuesdays 23:59 UTC, stable Tuesdays 20:00 UTC, nightly daily) — [gemini-cli README](https://github.com/google-gemini/gemini-cli)
- Hooks (introduced Jan 2026): 11 events `SessionStart`, `SessionEnd`, `BeforeAgent`, `AfterAgent`, `BeforeModel`, `AfterModel`, `BeforeToolSelection`, `BeforeTool`, `AfterTool`, `PreCompress`, `Notification`; JSON `hooks` object in `.gemini/settings.json` (project) > `~/.gemini/settings.json` > `/etc/gemini-cli/settings.json` > extension-defined; only `type: "command"`; matchers are regex for `BeforeTool`/`AfterTool`; stdin JSON, stdout must be only a JSON object (otherwise the CLI defaults to Allow); exit 0 parse JSON, exit 2 system block (stderr = reason), other = warning; timeout default 60000 ms. Page last updated 2026-04-13; does not say whether hooks run in headless mode — [geminicli.com/docs/hooks](https://geminicli.com/docs/hooks/); [Google Developers Blog, hooks](https://developers.googleblog.com/en/tailor-gemini-cli-to-your-workflow-with-hooks/)
- Headless: triggered by a non-TTY or `-p/--prompt`; `--output-format` json (`response`, `stats`, optional `error`) or streaming JSONL (events `init`, `message`, `tool_use`, `tool_result`, `error`, `result`); exit codes 0 success, 1 general/API error, 42 input error, 53 turn limit exceeded. Page last updated 2026-03-10 — [Headless mode](https://geminicli.com/docs/cli/headless/)
- Policy engine: TOML `[[rule]]` files in `~/.gemini/policies/`; decisions `allow`, `deny` (global deny removes the tool from the model's view), `ask_user`; priority tiers Default(1) < Extension(2) < Workspace(3, "currently disabled") < User(4) < Admin(5) with `tier_base + toml_priority/1000`; matchers `toolName` (wildcards incl. `mcp_*`), `argsPattern` regex, `commandPrefix`/`commandRegex`, `mcpName`, `toolAnnotations`, `subagent`, `modes` (`default`, `autoEdit`, `plan`, `yolo`), `interactive`; **in non-interactive mode `ask_user` is treated as `deny`** — [Policy engine](https://geminicli.com/docs/reference/policy-engine.md); v0.31.0 (2026-02-27) added project-level policies, MCP wildcards, tool-annotation matching — [changelog mirror](https://www.mintlify.com/google-gemini/gemini-cli/resources/changelog)
- README-advertised auth (possibly stale, see next bullet): Google login free tier 60 req/min and 1,000 req/day with Gemini 3 models and 1M context; Gemini API key free tier 1,000 req/day; Vertex AI; `GEMINI.md` context files; conversation checkpointing to save/resume; "Sandboxing & Security" with a Dockerfile in the repo — [gemini-cli README](https://github.com/google-gemini/gemini-cli)
- **Consumer shutdown**: Google's blog (2026-05-19) says that on 2026-06-18 Gemini CLI and Gemini Code Assist IDE extensions stop serving requests for Google AI Pro/Ultra subscribers and for Gemini Code Assist for individuals (the free tier); organizations with Code Assist Standard/Enterprise licenses keep access; Gemini CLI "remains accessible with paid Gemini and Gemini Enterprise Agent Platform API keys"; Agent Skills, Hooks, Subagents and Extensions (renamed "Antigravity plugins") carry over to Antigravity CLI, "no 1:1 feature parity right out of the gate" — [Google Developers Blog](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/); the docs banner reads "Unpaid tier and Google One users: Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" — [Headless mode page](https://geminicli.com/docs/cli/headless/)
- Antigravity CLI (`agy`): described by third parties as a closed-source Go binary with `agy -p` headless mode and hooks carried over; Google AI Pro $20/mo; free tier about 20 agent requests/day — [pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/3422/antigravity-cli-agy-install-migrate-gemini-cli); [ostechnix](https://ostechnix.com/google-is-replacing-gemini-cli-with-google-antigravity/); Google Cloud community hooks guide (2026-06-26) — [medium/google-cloud](https://medium.com/google-cloud/a-developers-guide-to-agent-hooks-in-antigravity-cli-4c1440febd11); a Google AI forum reply says running the unmodified `agy` binary headless from a script under your own account is permitted while third-party tools that extract OAuth tokens are prohibited (informal, not policy) — [discuss.ai.google.dev](https://discuss.ai.google.dev/t/headless-agy-runs-launched-by-a-script-from-another-ai-coding-tool-within-the-additional-terms/185494); Flutter docs call `agy` the successor to "the legacy Gemini CLI" — [docs.flutter.dev](https://docs.flutter.dev/ai/antigravity-cli)

#### OpenCode (anomalyco/opencode, formerly sst/opencode)

- Non-interactive: `opencode run` with `--continue/-c`, `--session/-s`, `--fork`, `--share`, `--model/-m`, `--agent`, `--file/-f`, `--format json` (raw JSON events), `--title`, `--attach http://host:4096` (run against a remote server), `--dir`, `--port`, `--variant`, `--thinking`, `--auto` (auto-approve permissions not explicitly denied); `opencode acp` (ACP over stdin/stdout nd-JSON); `opencode web`; `opencode auth login --provider --method`; credentials at `~/.local/share/opencode/auth.json` — [CLI docs](https://opencode.ai/docs/cli/)

## KQ2. Which harnesses expose a post-turn or post-task hook/event a container could use to publish status to MQTT (like Claude Code's Stop hook)?

### Takeaway
Most 2026 harnesses copied Claude Code's hook model nearly verbatim, so a `Stop`/`AfterAgent`/`agent_end`-class shell hook is available in Codex, Gemini CLI, Qwen Code, Droid, Cursor, Vibe, Kimi, OpenCode (plugin), Pi (extension) and Hermes (plugin/gateway/outbound webhook); the harnesses without one (Goose, Kilo, OpenHands CLI, Aider, Crush "preliminary", Copilot CLI unconfirmed) can still be wrapped by tailing their JSONL stream output, which every harness now emits.

### Cited Findings
- Codex: `Stop` (input includes `stop_hook_active`, `last_assistant_message`), `SessionEnd` (`reason`), `SubagentStop`, `PostToolUse`; `codex exec --json` emits `turn.completed` with token usage — [Codex hooks](https://learn.chatgpt.com/docs/hooks.md), [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode.md)
- Gemini CLI: `AfterAgent`, `SessionEnd`, `AfterTool`, `Notification` hooks; headless `stream-json` emits a terminal `result` event — [geminicli.com/docs/hooks](https://geminicli.com/docs/hooks/), [Headless](https://geminicli.com/docs/cli/headless/)
- OpenCode: plugin events `session.idle`, `session.status`, `session.updated`, `message.updated`, `tool.execute.after`; the server also streams the same bus over SSE at `GET /event`, so an out-of-process sidecar needs no plugin at all — [Plugins](https://opencode.ai/docs/plugins/), [Server](https://opencode.ai/docs/server/)
- Pi: `agent_end`, `turn_end`, `agent_settled`, `session_shutdown`, `tool_result`; extensions "load in interactive, RPC, JSON, and print modes" — [extensions.md](https://raw.githubusercontent.com/earendil-works/pi-mono/main/packages/coding-agent/docs/extensions.md)
- Hermes: plugin hooks `on_session_end`, `on_session_finalize`, `agent_loop_stopped`, `post_tool_call`, `post_llm_call`, `subagent_stop`; gateway hooks `agent:end`, `agent:step`, `session:end`; outbound webhooks push signed lifecycle events to HTTP endpoints; shell hooks in `config.yaml` — [Hermes hooks](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks)

### Inferences
- Shell-hook JSON conventions (stdin JSON with `session_id`/`cwd`/`hook_event_name`, exit 2 = block, `hookSpecificOutput`) are close enough across Codex, Droid, Qwen, Gemini and Cursor that Saga's existing `dvergr-hooks` Stop-hook script could be ported with only payload-field renames.

## KQ3. Which harnesses have a first-class "loop until done" mechanism comparable to Claude Code's /ralph-loop plugin?

### Takeaway
Only Hermes (`/goal` with a judge model, completion contracts, quality gates and a 20-turn budget) and OMO (Todo enforcer + `ultrawork`) ship an opinionated "keep going until done" loop; Codex and Droid expose the same *primitive* Claude Code uses (a blockable `Stop` hook with `stop_hook_active`), Pi exposes `agent_before_settle` (one-continuation request) for extensions, and Qwen Code has a `/loop` skill plus `StopFailure` loop detection; the rest rely on external schedulers (Goose recipes, Hermes cron, Cline `schedule`) or turn/time budgets (Vibe) rather than a completion-driven loop.

### Cited Findings
- Hermes `/goal`: judge verdicts `done|continue|blocked|wait`; continuation prompt appended as a user message; `goals.max_turns` default 20; `/subgoal`; completion contracts; quality gates (shell commands that must exit 0 before the judge); persists across `/resume`; not available over ACP — [Hermes goals](https://hermes-agent.nousresearch.com/docs/user-guide/features/goals); `/loop` timer-driven; cron for unattended/restart-surviving work — [Hermes loops](https://hermes-agent.nousresearch.com/docs/user-guide/features/loops), [Hermes cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)
- OMO: "Todo enforcer pulls an idle agent back to finish its task"; `ultrawork`/`ulw` "activates all agents until the task is done"; Hephaestus "autonomous deep worker" — [v3.11.0 README](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v3.11.0/README.md); `ulw` makes the agent "read the codebase, plan, verify each step, and stop when done"; `mass ulw` agent graph "checked before completion" — [GitHub README](https://github.com/code-yeongyu/oh-my-openagent)
- Codex `Stop` hook: input `stop_hook_active`, `last_assistant_message`; output `continue`/`stopReason`; plain-text stdout is invalid for `Stop` — [Codex hooks](https://learn.chatgpt.com/docs/hooks.md); `--approve-for-me` / `approvals_reviewer = auto_review` routes approvals to a reviewer agent so runs don't block — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode.md), [Sandboxing](https://learn.chatgpt.com/docs/sandboxing.md)
- Droid `Stop` hook: exit 2 or `{"decision":"block","reason":"..."}` "prevents stopping"; `stop_hook_active`, `tool_execution_count`, `elapsed_time` inputs — [Droid hooks](https://docs.factory.com/reference/hooks-reference.md)
- Pi: `agent_before_settle` "(can request one continuation)" — [extensions.md](https://raw.githubusercontent.com/earendil-works/pi-mono/main/packages/coding-agent/docs/extensions.md)
- Qwen Code: built-in `/loop` skill; `StopFailure` hook "for loop detection"; `TodoCreated`/`TodoCompleted` events — [GitHub README](https://github.com/QwenLM/qwen-code), [Qwen hooks](https://raw.githubusercontent.com/QwenLM/qwen-code/main/docs/users/features/hooks.md)
- Gemini CLI: headless exit code 53 "turn limit exceeded"; `AfterAgent` hook exists — [Headless](https://geminicli.com/docs/cli/headless/), [Hooks](https://geminicli.com/docs/hooks/)
- Mistral Vibe: `--max-turns`, `--max-price`, `--max-tokens`, `--time-limit` budgets — [GitHub README](https://github.com/mistralai/mistral-vibe)
- Goose: Recipes (portable YAML) runnable headless/CI; scheduler — [mcp.directory (via search)](https://mcp.directory/blog/goose-vs-opencode-2026); Cline: `cline schedule` — [CLI overview](https://docs.cline.bot/cli/overview)
- Cursor: headless runs "drain delegated subagents and include their completion before exiting" (not a loop) — [Cursor CLI changelog](https://cursor.com/docs/cli/changelog)

### Inferences
- A Ralph loop for Codex or Droid workers can be built with the same Stop-hook-returns-"block" trick Saga already uses, with Odin's iteration cap enforced via `stop_hook_active`/`tool_execution_count`.
- Hermes's judge-with-quality-gates design is the closest existing analogue to Saga's Odin+Mimir split (judge = Mimir-lite, quality gate = deterministic test command) and could inform how Odin decides when a dvergr is "done".
- Pi's single-continuation primitive implies a loop would be an extension that re-arms itself each `agent_before_settle`, which is simple but not documented as a supported pattern.

### Gaps
- Whether Gemini CLI's `AfterAgent` can veto stopping (i.e. force continuation) is not documented on the hooks page.
- Droid "Mission Mode" (requires `--auto high`) was named but not described in the fetched docs.
- No evidence that OpenCode, Kilo, Crush, Cursor, Copilot or Amp ship a built-in completion loop.

## KQ5. State of harness-agnostic protocols (ACP) and whether driving an agent over ACP preserves its native subscription billing

### Takeaway
ACP is at protocol version 1 with 43 listed agents (most native, Claude/Codex/Pi via adapters) and stdio-only transport in production; it preserves native billing by construction because the agent runs its own client and credentials (Goose sells this explicitly), but for Claude the relevant question is Anthropic policy, not ACP: as of 2026-10-07 Anthropic's support page says Agent SDK, `claude -p` and third-party apps "still draw from your subscription limits", while harnesses that do their own OAuth (OpenCode, Hermes) are blocked.

### Cited Findings
- ACP agents list (43): AgentPool, Augment Code, AutoDev, Blackbox AI, Bub (adapter), Claude Agent (via Zed's SDK adapter `claude-agent-acp`), Claw Orchestrator, Cline, Codex CLI (via `codex-acp` adapter), Code Assistant, Construct, crow-cli, CUGA, Cursor, Docker cagent, fast-agent, Factory Droid, fount, Gemini CLI, GitHub Copilot (public preview, 2026-01-28), Goose, Hermes Agent, Junie (JetBrains), Kaagum, Kimi CLI, Kiro CLI, localharness, Minion Code, Mistral Vibe, Muse Spark Code (unofficial), OpenClaw, OpenCode, OpenHands, Pi (via `pi-acp`), Poolside, Qoder CLI, Qwen Code, Raven, Raxol, siGit Code, Stakpak, stdio Bus, VT Code — [ACP agents](https://agentclientprotocol.com/overview/agents)
- Protocol version 1 stable; `schema/v1` and `schema/v2` artifacts; SDKs Kotlin, Java, Python, Rust, TypeScript; Apache-2.0 — [ACP GitHub](https://github.com/agentclientprotocol/agent-client-protocol); local agents as subprocesses over JSON-RPC/stdio; remote HTTP/WebSocket "a work in progress" — [ACP introduction](https://agentclientprotocol.com/overview/introduction); third-party claims of a stable v1 at schema 1.24.1 (2026-09-30) and a v2 draft (2026-07-20) — [danilchenko.dev](https://www.danilchenko.dev/posts/ai-agent-protocols/) (unverified)
- Clients named in harness docs: Zed (ACP registry), JetBrains (`acp.json`), Avante.nvim, CodeCompanion.nvim — [OpenCode ACP](https://opencode.ai/docs/acp/); Toad, Zed, VSCode, JetBrains — [OpenHands-CLI README](https://github.com/OpenHands/OpenHands-CLI); Emacs `agent-shell` mentioned by an HN user — [HN thread](https://hn.svelte.dev/item/47633568)
- Billing via ACP: Goose's `claude-acp` uses the installed, authenticated Claude CLI, `chatgpt_codex` uses a browser ChatGPT sign-in, `gemini_oauth` a Google sign-in, "use what you already pay for" — [goose blog 2026-03-19](https://goose-docs.ai/blog/2026/03/19/use-goose-with-your-ai-subscription); Zed's Claude Agent thread offers `/login` with API key or Pro/Max subscription — [Zed external agents](https://zed.dev/docs/ai/external-agents)
- Anthropic position: June 15, 2026 pause of the Agent SDK credit change; October 7, 2026: "You can still use the Claude Agent SDK, `claude -p`, and third-party apps with your subscription limits", plus new monthly API credits on Max/Team — [support.claude.com 15036540](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan); Zed's June 16 addendum: ACP usage, `claude -p`, Agent SDK and third-party SDK apps "still work with subscriptions as before" — [Zed blog](https://zed.dev/blog/anthropic-subscription-changes)
- Contradicting enforcement: Hermes via its own Claude OAuth got `HTTP 400: Third-party apps now draw from your extra usage, not your plan limits` on 2026-09-01, while `claude -p` from the same machine worked — [codenote.net](https://codenote.net/en/posts/hermes-agent-claude-third-party-extra-usage-http-400/); OpenCode's docs: "Anthropic explicitly prohibits this" for third-party Pro/Max plugins — [OpenCode providers](https://opencode.ai/docs/providers/)
- Limits of ACP-wrapped agents: Goose ACP providers cannot resume or fork sessions — [goose ACP providers (via search)](https://goose-docs.ai/docs/guides/acp-providers); Hermes `/goal` is not supported over ACP — [Hermes goals](https://hermes-agent.nousresearch.com/docs/user-guide/features/goals); OpenCode `/undo`/`/redo` unsupported over ACP — [OpenCode ACP](https://opencode.ai/docs/acp/)
- Codex ACP uses the `codex-acp` adapter; Codex's own embedding protocol is "app-server" (the Codex MCP server was removed) — [ACP agents](https://agentclientprotocol.com/overview/agents), [learn.chatgpt.com/llms.txt](https://learn.chatgpt.com/llms.txt)

### Inferences
- The billing-preserving distinction is "who holds the credential": an ACP adapter that spawns the vendor's own CLI/SDK (claude-agent-acp, codex-acp, Goose's providers) inherits that CLI's billing; a harness that implements the vendor's OAuth itself (OpenCode's removed plugin, Hermes's Claude OAuth, Pi community packages) is what Anthropic blocks.
- Anthropic's Oct 7, 2026 wording that `claude -p` still draws from subscription limits conflicts with Saga's own April 10, 2026 finding (recorded in CLAUDE.md) that `claude -p` required an API key; the official position has moved at least twice (announced split May 14, paused June 15, credits added Oct 7), so a re-test of `claude -p` inside the dvergr container with the credentials volume is warranted before treating "interactive only" as a hard constraint.
- Because ACP is stdio-only in production and session resume is adapter-dependent, ACP is a reasonable way for Odin to *drive* a worker in-container, but not a substitute for Saga's MQTT journal as the cross-container status bus.

### Gaps
- No OpenAI or Google statement found on whether driving Codex/Gemini over ACP (or Goose's `chatgpt_codex`/`gemini_oauth` providers) is within their subscription terms; the Google forum reply on headless `agy` is informal.
- ACP governance (whether still Zed-led or foundation-hosted) not confirmed; `GOVERNANCE.md` not read.
- Whether claude-agent-acp still works with Pro/Max as of October 2026 (not just per policy text) was not verified by a dated user report.

## KQ6. Which subscriptions can be used headless inside a container, per harness, as of October 2026?

### Takeaway
ChatGPT (Codex CLI, with documented device-code/auth.json/access-token paths; also accepted by OpenCode, OMO, Amp, Goose) and GitHub Copilot (Copilot CLI via PAT; OpenCode device-code; Pi `COPILOT_GITHUB_TOKEN`) are the subscriptions with a clean, vendor-tolerated headless story; Kimi Code's RFC 8628 device-code login and the $10 OpenCode Go / GLM Coding Plan keys are the cheap options; Claude subscriptions are first-party-only (Claude Code, `claude -p`/Agent SDK per Anthropic's Oct 7 page); Google consumer subscriptions no longer work in the open-source Gemini CLI at all.

### Cited Findings
- Codex: ChatGPT sign-in = subscription access; `codex login --device-auth` (beta, must be enabled in ChatGPT settings); copy `~/.codex/auth.json` via `docker cp`; enterprise access tokens via `--with-access-token`; CI guidance to seed `auth.json` and persist refreshed file — [Codex auth](https://learn.chatgpt.com/docs/auth), [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode.md); Plus $20 includes CLI with ~350–3,000 GPT-6 Luna messages/5h; Pro from $100 with no 5-hour limit "currently" — [Codex pricing](https://learn.chatgpt.com/docs/pricing.md)
- OpenCode: ChatGPT Plus/Pro OAuth, GitHub Copilot device-code, GitLab Duo "zero setup"; Claude Pro/Max "Anthropic explicitly prohibits this"; OpenCode Go $10/mo — [OpenCode providers](https://opencode.ai/docs/providers/), [opencode.ai/go](https://opencode.ai/go)
- OMO `/login`: Claude, ChatGPT, Kimi, GLM subscriptions listed (Claude listing conflicts with Anthropic policy) — [GitHub README](https://github.com/code-yeongyu/oh-my-openagent); earlier: ChatGPT $20, Kimi Code, GLM Coding Plan $10 — [v3.11.0 README](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v3.11.0/README.md)

- Goose: `chatgpt_codex` (browser sign-in, cached session), `gemini_oauth`, `claude-acp` (requires authenticated Claude CLI) — [goose blog](https://goose-docs.ai/blog/2026/03/19/use-goose-with-your-ai-subscription)

- Gemini CLI: free/consumer tiers stopped 2026-06-18; paid Gemini API keys and Code Assist Standard/Enterprise continue — [Google blog](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/); Antigravity CLI with Google AI Pro ($20/mo, per third party) — [pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/3422/antigravity-cli-agy-install-migrate-gemini-cli)
- Droid: `FACTORY_API_KEY` headless; Pro $20/Plus $100/Max $200 include the CLI and SDK — [droid exec](https://docs.factory.com/droid-exec/overview.md), [Factory plans](https://docs.factory.ai/pricing/individuals)

### Inferences
- A Codex dvergr is feasible with Saga's existing credentials-volume pattern: mount a volume containing `~/.codex/auth.json` and let Codex refresh it in place, exactly as the docs prescribe for CI; the operator's keepalive concern applies there too.

- GitHub Copilot is the most "harness-portable" subscription (Copilot CLI, OpenCode, Pi, Kilo-via-OpenCode-fork likely), but its per-prompt premium-request metering is a poor fit for many-iteration Ralph loops.

## KQ7. Synthesis: which architectural patterns are now common and which are distinctive

### Takeaway
"Table stakes" in Oct 2026: AGENTS.md, Agent Skills (`SKILL.md`), MCP, lifecycle shell hooks with JSON I/O and exit-2 blocking, a headless print/exec mode emitting JSONL, session resume/fork, subagents, permission policies (allow/ask/deny), git-worktree isolation and an ACP server mode. Distinctive: OpenCode's server-first/SSE design, Pi's extension-only core with RPC mode, Hermes's judge-driven goals + learning loop + messaging gateway + outbound webhooks, Codex's reviewer-agent approvals and hash-trusted hooks, Gemini's tiered policy engine, Droid's autonomy tiers, OMO's Hashline/IntentGate/Todo enforcer, and Qwen's `http` hook type.

### Inferences
- Because the hook and JSONL conventions converged on Claude Code's shape, Saga's per-iteration MQTT publishing (Stop hook → mosquitto_pub) can be made harness-agnostic with a thin adapter layer: a per-harness hook stub plus a stdout-JSONL tailer as fallback, with the journal schema unchanged.
- For a mixed-harness Saga, the natural first non-Claude worker is Codex (documented container auth, Stop hook with `last_assistant_message`, subagent/sandbox inheritance rules, `--output-schema` for structured iteration summaries), the second is a Pi worker with a custom extension (Ralph loop + MQTT in TypeScript), and OpenCode is the best base if Saga wants a server-mode worker that Odin drives over HTTP/SSE with a ChatGPT/Copilot/Go subscription.
- The planner (Odin) can borrow from Hermes (judge verdicts, quality gates, completion contracts), Gemini (declarative policy tiers with headless deny-by-default), and Codex (AGENTS.md layering, reviewer-agent approvals) without changing harness.

### Gaps
- No single 2026 benchmark or practitioner comparison with reproducible methodology across these harnesses was found in this pass; popularity signals are GitHub stars and release cadence only.
- Several vendor-specific claims (Amp billing changes, Antigravity free-tier quota, OpenCode Go subscriber count, Pi acquisition terms) rest on single secondary sources.
